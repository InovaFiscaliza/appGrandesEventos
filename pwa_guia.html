💡 O que é uma PWA e como o WhatsApp usa isso

Uma PWA (Progressive Web App) é um site que se comporta como um app nativo. O WhatsApp Web usa exatamente essa técnica: ele registra um Service Worker no navegador, que funciona como um proxy entre o app e a internet.

Quando a conexão cai, o Service Worker intercepta as requisições e serve páginas que estão salvas em cache local — por isso o WhatsApp continua abrindo mesmo offline.

1Usuário acessa o app com internet
→
2Service Worker é instalado e faz cache das páginas
→
3Internet cai
→
4SW serve do cache — app continua funcionando

📄 Passo 1 – app/static/manifest.json

O manifest.json é a "carteira de identidade" do app. Ele diz ao navegador como o app deve se chamar, qual ícone usar e como abrir.

📁 app/static/manifest.json
{
  "name": "AppEventos",
  "short_name": "Eventos",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#0078d4",
  "icons": [
    { "src": "/static/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/static/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}

display: standaloneEsconde a barra do navegador — parece app nativo
theme_colorCor da barra de status do Android
iconsÍcone na tela inicial e na splash screen

⚙️ Passo 2 – app/static/sw.js

O Service Worker é um script JavaScript que roda em segundo plano no navegador, interceptando todas as requisições de rede. Usa a estratégia Network First com fallback para cache — igual ao WhatsApp.

📁 app/static/sw.js
const CACHE = "appEventos-v1";
const SHELL = [
  "/static/style.css",
  "/static/offline.html",
];

// Instalação: pré-carrega os assets essenciais
self.addEventListener("install", e => {
  e.waitUntil(
    caches.open(CACHE).then(c => c.addAll(SHELL))
  );
  self.skipWaiting();
});

// Ativação: remove caches de versões antigas
self.addEventListener("activate", e => {
  e.waitUntil(
    caches.keys().then(keys =>
      Promise.all(keys.filter(k => k !== CACHE).map(k => caches.delete(k)))
    )
  );
  self.clients.claim();
});

// Fetch: tenta a rede primeiro, cai para cache se offline
self.addEventListener("fetch", e => {
  if (e.request.method !== "GET") return;

  e.respondWith(
    fetch(e.request)
      .then(res => {
        const clone = res.clone();
        caches.open(CACHE).then(c => c.put(e.request, clone));
        return res;
      })
      .catch(() =>
        caches.match(e.request).then(cached =>
          cached || caches.match("/static/offline.html")
        )
      )
  );
});

Estratégia Network First

1Tenta buscar da rede (Google Sheets, etc.)
→
2Se ok: salva no cache e retorna
→
3Se falhou: busca do cache local
→
4Se não tem cache: mostra offline.html

🖼️ Passo 4 – Atualizar app/templates/base.html

Adicionar o link para o manifest e o script de registro do Service Worker.

📁 app/templates/base.html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>AppEventos</title>
    <link rel="stylesheet" href="/static/style.css">

    <!-- PWA: identidade do app -->
    <link rel="manifest" href="/static/manifest.json">
    <meta name="theme-color" content="#0078d4">
</head>
<body>
<div class="container">
{% block content %}{% endblock %}
</div>

<!-- PWA: registrar o Service Worker -->
<script>
  if ('serviceWorker' in navigator) {
    navigator.serviceWorker.register('/sw.js')
      .then(r => console.log('SW registrado:', r.scope))
      .catch(e => console.error('SW falhou:', e));
  }
</script>
</body>
</html>

🐍 Passo 5 – Rota /sw.js em main.py

O Service Worker deve ser servido da raiz (/sw.js), não de /static/sw.js. Adicione esta rota no main.py:

📁 main.py — adicionar após app.mount("/static", ...)
from fastapi.responses import FileResponse

@app.get("/sw.js", include_in_schema=False)
async def service_worker():
    return FileResponse("app/static/sw.js", media_type="application/javascript")
⚠️ Por que na raiz? O Service Worker só tem controle sobre URLs dentro do seu escopo. Um SW em /static/sw.js só controlaria páginas dentro de /static/. Na raiz (/sw.js), ele controla todo o app.

SituaçãoComportamento

Celular/computador — "Adicionar à tela inicial"Ícone aparece, abre sem barra do navegador

Tenta abrir página nunca visitada offlineMostra a página "Você está offline"

⚠️ Limitação dos dados: Os dados do Google Sheets só ficam disponíveis offline se a página foi visitada com internet previamente. Para dados sempre disponíveis offline, seria necessário adicionar IndexedDB para persistência local no navegador — uma etapa futura opcional.
