01 · A arquitetura em uma página

O AppGrandesEventos organiza a monitoração do espectro em eventos: emissões, incidentes, estações, fiscais, tickets, escalas e testes de etiquetagem. É uma aplicação web com um servidor Python e páginas HTML. A organização atual concentra bastante lógica nas rotas e no serviço de dados.

NavegadorHTML · CSS · JavaScript
↔
FastAPImain.py + routers
↔
Serviçospostgres.py + db.py
↔
PostgreSQLTabelas e relacionamentos

O que roda no servidor?

Python recebe os pedidos, verifica a sessão e as permissões, consulta o banco e prepara as respostas. Jinja2 transforma templates em HTML antes de enviá-los ao navegador.

O que roda no navegador?

HTML define os elementos. CSS define o visual. JavaScript responde aos cliques, abre popups, busca JSON e mantém filas offline em IndexedDB.

Vocabulário: rota é um endereço atendido pelo servidor; template é um modelo de HTML; serviço é uma função que executa uma operação; API é uma rota que troca dados, geralmente em JSON. GET busca uma página ou dados. POST envia dados para processamento.

Não há um frontend React separado neste projeto. Há páginas renderizadas com Jinja2 e algumas áreas preenchidas por JavaScript. SQLAlchemy gerencia conexões e executa consultas SQL; o acesso principal aos dados está em funções de postgres.py, sem uma camada de modelos ORM separada.

03 · Acompanhe uma requisição

Exemplo real: a coordenação seleciona registros e cria um ticket. Clique nas etapas para seguir o caminho.

HTML e JavaScript preparam o envio

Em app/templates/coordenacao.html, o botão abre o popup. O formulário ticket-form envia para POST /coordenacao/ticket. Os checkboxes das tabelas usam form="ticket-form": mesmo fora do formulário, fazem parte do envio.

<input type="checkbox" name="incidente_ids" value="42" form="ticket-form">
<form id="ticket-form" method="post" action="/coordenacao/ticket">
    <select name="prioridade">...</select>
    <button type="submit">Criar ticket</button>
</form>

A rota recebe e valida

post_ticket_evento(), em app/routers/coordenacao.py, obtém o evento da sessão, verifica o papel do usuário, lê await request.form() e usa getlist() para os campos com vários valores. Se nenhum registro foi selecionado, devolve uma mensagem de erro.

O serviço grava no banco

A rota chama salvar_ticket_evento() em app/services/postgres.py. Essa função recebe IDs e campos, aplica as regras de persistência e salva ticket e vínculos. A rota também chama registrar_auditoria_coordenacao().

Abra a função e acompanhe as consultas e a transação. A operação precisa manter o ticket consistente com as emissões, incidentes e fiscais atribuídos.

O navegador recebe a resposta

A rota guarda flash_success na sessão e responde com redirecionamento 303 para /coordenacao. O navegador faz um novo GET; a rota lê os dados atualizados e renderiza o template. Este padrão evita repetir o POST ao atualizar a página.

Como reconhecer os três tipos de dado

  • request.query_params: parâmetros na URL, como ?editar=42&ticket_id=7.
  • await request.form(): valores enviados por formulário; o atributo name define a chave.
  • request.session: contexto do usuário, como evento, fiscal e papel selecionados.

id identifica um elemento para JavaScript e rótulos. name identifica um campo enviado ao Python. Eles têm funções diferentes.

05 · Como os dados se relacionam

O evento é o contexto central. Nas operações, confira o evento_id para não misturar dados de eventos diferentes. “Emissão” na interface corresponde principalmente à tabela ocorrencias. “Incidente” corresponde a bsr_erb.

eventos
├── estacoes ── ocorrencias (emissões)
├── bsr_erb (incidentes)
├── eventos_fiscais ── fiscais
├── eventos_coordenadores ── fiscais
├── escalas_trabalho ── fiscais
├── tickets
│   ├── ticket_ocorrencias ── ocorrencias
│   ├── ticket_incidentes ── bsr_erb
│   └── ticket_fiscais ── fiscais
├── tabela_ute
└── testes_etiquetagem

Mapa conceitual simplificado: não representa todas as colunas e chaves estrangeiras. Consulte db/schema.sql para a definição exata.

Tabelas de vínculo

Um ticket pode ter vários fiscais e vários registros. ticket_fiscais, ticket_ocorrencias e ticket_incidentes representam essas relações. Não transforme uma relação em um campo de texto sem estudar as consultas existentes.

Imagens e auditoria

Há tabelas específicas para imagens e históricos, como ocorrencia_imagens, bsr_erb_imagens, auditoria_ocorrencias e auditoria_bsr_erb. Verifique esses caminhos quando alterar anexos ou gravação.

Nomes antigos ainda aparecem

spreadsheet_id na sessão representa o ID do evento no PostgreSQL. Algumas funções mantêm nomes da integração anterior com planilhas. O comentário inicial de postgres.py explica essa compatibilidade. Não conclua pelo nome que a operação ainda usa Google Sheets.

Quando adicionar uma coluna

  1. Entenda a entidade e defina tipo, obrigatoriedade e valor padrão.
  2. Prepare uma migração SQL conforme local_server/migrations/README.md e mantenha a definição de referência coerente.
  3. Atualize INSERT, UPDATE e SELECT no serviço.
  4. Atualize rota, formulário e renderização.
  5. Se o dado é editável offline, revise também fila, API de sincronização e cache.
  6. Aplique e verifique primeiro em uma cópia de desenvolvimento do banco.

A coordenação pode devolver o ticket para pendente ou cancelá-lo por uma ação específica. Consulte os valores exatos em app/config.py e as transições em atualizar_ticket_evento() e cancelar_ticket_evento().

O popup de edição de um registro

  1. O fiscal clica em um número em tratamento_tickets.html.
  2. O JavaScript abre um iframe dentro de um popup.
  3. Emissão: /consultar?emissao_id=11&ticket_id=4&popup=1.
  4. Incidente: /bsr-erb?editar=42&ticket_id=4&popup=1.
  5. O modo popup=1 limita a interface ao registro selecionado. O servidor continua validando se o usuário pode editar.

Dois controles diferentes: esconder um botão ajuda a interface; verificar a permissão no servidor protege a operação. Uma pessoa pode enviar um POST sem clicar no botão. Por isso a rota de gravação precisa validar sessão, evento, vínculo e status.

request.state.permissoes orienta a visibilidade de módulos. As regras específicas também aparecem nos routers e serviços: _load_pendencias() em consultar.py, _ticket_autoriza_edicao_incidente() em bsr_erb.py e funções do módulo de tratamento. Leia a implementação atual: os comentários nem sempre acompanham todas as mudanças.

A sessão usa cookie assinado por SessionMiddleware. No código atual, a chave é gerada na inicialização, então reiniciar o servidor pode invalidar a sessão anterior. Essa sessão mantém o contexto de seleção do evento e fiscal; ela não deve ser confundida com um sistema completo de autenticação por senha.

Uma rotina manual que funciona

  1. Descreva a mudança em uma frase e um exemplo: “ao clicar no ID 42, mostrar só o formulário do incidente 42”.
  2. Reproduza o comportamento e anote o endereço da tela.
  3. Pesquise esse endereço ou o texto do botão no projeto.
  4. Siga o fluxo: template → JavaScript → rota → serviço → banco.

08 · Exemplo: criar uma tela simples

Primeiro exercício: criar uma página de ajuda. A seção 13 traz um módulo completo com banco e popup. Os trechos abaixo são exemplos para você implementar manualmente; esta documentação não registra uma rota nova na aplicação.

1. Crie app/routers/ajuda.py

from fastapi import APIRouter, Request
from fastapi.responses import HTMLResponse
from fastapi.templating import Jinja2Templates

router = APIRouter()
templates = Jinja2Templates(directory="app/templates")

@router.get("/ajuda", response_class=HTMLResponse)
async def get_ajuda(request: Request):
    return templates.TemplateResponse(
        request,
        "ajuda.html",
        {"request": request,
         "evento_nome": request.session.get("evento_nome", "")},
    )

2. Crie app/templates/ajuda.html

{% extends "base.html" %}
{% block content %}
{% include "partials/header.html" %}
<section class="module-section">
    <h1>Ajuda</h1>
    <p>Selecione um módulo no menu para começar.</p>
    <a href="/menu" class="btn">Voltar ao menu</a>
</section>
{% endblock %}

3. Registre o router em main.py

# Junto aos imports dos routers:
from app.routers import ajuda

# Junto aos app.include_router(...):
app.include_router(ajuda.router)

4. Execute e confira

Inicie em modo de desenvolvimento, selecione evento e fiscal pela tela inicial e abra http://localhost:8501/ajuda. O middleware atual exige sessão para essa rota. Se funcionar, adicione um link para /ajuda ao menu.

Como ler a sintaxe de Jinja2
  • {{ evento_nome }} imprime um valor do contexto Python.
  • {% if condicao %}...{% endif %} mostra um trecho condicionalmente.
  • {% for item in itens %}...{% endfor %} repete elementos.
  • {% extends "base.html" %} usa uma estrutura compartilhada.
  • {% include "partials/header.html" %} inclui outro template.

Esses comandos são executados no servidor. O navegador recebe o HTML resultante.

Exercício seguinte: entender um popup

Crie um botão type="button" e um contêiner com hidden. No JavaScript, conecte o clique do botão a popup.hidden = false; conecte o botão de fechar a popup.hidden = true. Só depois acrescente um formulário e uma rota POST. Dentro de um formulário, omitir type="button" pode fazer um botão enviar os dados por engano.

09 · A camada offline também precisa de atenção

Cache de arquivos

sw.js é o Service Worker. Mantém recursos em cache e usa estratégias para requisições. main.py serve esse arquivo em /sw.js para que tenha escopo na aplicação.

Dados e filas locais

app.js expõe AppOffline e usa IndexedDB. sync.js envia operações pendentes quando a conexão volta. db.js hoje é apenas um arquivo de compatibilidade.

Fila no navegador       → rota de sincronização
fila_envio              → POST /api/inserir
fila_bsr_erb            → POST /api/bsr-erb
fila_edicoes            → POST /api/consultar-salvar

connectivity.js acompanha a conectividade, e app/utils/offline.py prepara contextos usados nos retornos offline. Uploads de fotos merecem verificação específica: arquivos multipart não são equivalentes aos objetos JSON dessas filas.

Ao mudar um campo, uma permissão ou uma API de edição, confira tanto o envio normal quanto a sincronização offline. Ao mudar JavaScript ou CSS, verifique a versão na URL do recurso e o cache do Service Worker se o navegador continuar mostrando código antigo.

11 · Uma sequência para aprender no próprio projeto

  1. HTML e formulários: leia tratamento_tickets.html; identifique tabela, botões, name e action. Exercício: mudar um rótulo.
  2. CSS: localize as classes no style.css. Exercício: ajustar o espaçamento de uma área específica.
  3. JavaScript: acompanhe os cliques que abrem popups. Exercício: incluir um título com o ID selecionado usando textContent.
  4. Python: estude função, dicionário, lista, if, for e tratamento de exceções. Exercício: explicar as entradas e saídas de post_ticket_evento().
  5. FastAPI e Jinja2: faça a tela de ajuda do exemplo. Exercício: passar uma variável Python e mostrá-la no HTML.
  6. SQL: estude SELECT, JOIN, INSERT, UPDATE, chave estrangeira e transação. Exercício: acompanhar uma consulta de listagem no serviço.
  7. Regras do domínio: siga um ticket da criação ao encerramento e identifique as permissões de cada etapa.
  8. Offline: acompanhe uma fila desde a gravação local até a API de sincronização.

Para ganhar autonomia, termine cada exercício respondendo: “qual arquivo recebe a entrada?”, “qual função decide o resultado?” e “onde o dado é gravado?”. Quando essas respostas ficam claras, fica mais fácil planejar a próxima alteração.

12 · Entenda o código em detalhe

Uma variável percorre várias camadas

Imagine o campo titulo. No HTML, o usuário digita em <input name="titulo">. O navegador envia uma chave chamada titulo no POST. Python lê form.get("titulo", ""). O serviço remove espaços, valida o tamanho e entrega o valor ao SQL. O SELECT devolve um dicionário; Jinja2 exibe {{ tarefa.titulo }}. Um nome errado em qualquer etapa pode interromper esse caminho.

name="titulo"HTML
→
form.get("titulo")Python
→
INSERT / UPDATESQL
→
tarefa.tituloTemplate

Como ler uma função Python

def listar(evento_id):       # entrada: evento a consultar
    with conexao() as conn:  # controla abertura e fechamento
        return [...]        # saída: lista de registros

def declara uma função. Os parâmetros são entradas. return devolve o resultado. A indentação determina o bloco: as linhas recuadas pertencem à função, ao if ou ao with. async def permite usar await, por exemplo ao ler o formulário. Isso não transforma uma consulta SQL síncrona em assíncrona.

Listas e dicionários

tarefa = {"id": 7, "titulo": "Verificar entrada", "status": "pendente"}
tarefas = [tarefa]
print(tarefa["titulo"])              # acesso à chave obrigatória
print(tarefa.get("descricao", ""))   # padrão se a chave não existir

A listagem do exemplo é uma lista de dicionários. Cada linha SQL vira um dicionário por dict(row). No template, tarefa.titulo acessa a chave. Alguns serviços do sistema real devolvem DataFrames do pandas: leia o contrato antes de assumir o tipo de retorno.

GET, POST e redirecionamento

GET pede uma representação; POST envia uma operação. GET / monta a listagem, POST /tarefas cria e POST /tarefas/7/editar altera a tarefa 7. Depois de salvar, um 303 manda o navegador fazer GET. A mensagem fica na sessão e é retirada por pop() na próxima renderização.

Validação em três níveis

  1. Navegador: required, minlength e maxlength dão resposta rápida.
  2. Python: confirma valores mesmo quando um POST é enviado por outra ferramenta. Também verifica a permissão.
  3. Banco: NOT NULL e CHECK preservam restrições dos dados.

Um campo disabled não é enviado. Um campo apenas hidden continua podendo ser enviado: esconder não é autorização. O servidor sempre decide se a gravação é permitida.

SQL parametrizado

# SQLAlchemy + PostgreSQL: padrão do sistema e do exemplo
conn.execute(text("SELECT * FROM tickets WHERE evento_id = :evento_id"),
             {"evento_id": evento_id})

Os valores são enviados separadamente do SQL. Não concatene o título digitado em uma consulta. Uma transação agrupa alterações: faz commit ao concluir e rollback ao falhar. No exemplo, a edição verifica o registro e sua atribuição dentro de uma transação PostgreSQL com get_engine().begin() e bloqueio da linha por FOR UPDATE.

Como editar somente a linha escolhida

  1. O botão contém o ID em data-id.
  2. O clique localiza essa tarefa no array.
  3. form.reset() remove os valores da abertura anterior.
  4. O script preenche os campos e muda o action para a rota do ID selecionado.
  5. O servidor usa ID, evento e atribuição do banco para validar a alteração.

O exemplo usa <dialog> nativo: showModal() abre com controle de foco e Escape. O sistema real usa principalmente contêineres com hidden e, em alguns casos, iframes. Os mecanismos são diferentes, mas ambos mostram um formulário específico.

Separação de responsabilidades

A rota entende HTTP, sessão e mensagens. O serviço entende validação e SQL. O template entende apresentação. O JavaScript entende interação. Se o título é salvo incorretamente, veja o payload do POST. Se a posição do botão está errada, veja o template e o CSS.

Permissões

Ana e Bruno criam e editam somente suas tarefas. As demais aparecem para leitura. Coordenação pode editar, reatribuir e excluir. A interface respeita o perfil e o servidor valida novamente; mudar o HTML não concede permissão.

Diferenças para a aplicação real

  • O exemplo usa o mesmo módulo de conexão, o mesmo PostgreSQL e o mesmo padrão SQLAlchemy do sistema; somente a tabela didática fica no schema separado guia_programacao.
  • O evento é fixo e os fiscais são fictícios. Na aplicação, eventos e vínculos vêm do banco.
  • Não há auditoria, anexos, sincronização offline ou proteção CSRF de produção nesta demonstração.

Para integrar um módulo real

  1. Transforme as rotas em APIRouter e registre em main.py.
  2. Use a sessão existente, incluindo spreadsheet_id como ID do evento.
  3. Não copie a troca livre de perfil; use o usuário e as permissões reais.
  4. Incorpore as funções ao serviço real e conecte as relações com eventos e fiscais; os parâmetros SQL já seguem o padrão PostgreSQL do projeto.
  5. Prepare as migrações, relações e validações do domínio.
  6. Revise auditoria e offline conforme os requisitos do módulo.

CREATE SCHEMA IF NOT EXISTS guia_programacao;
CREATE TABLE IF NOT EXISTS guia_programacao.tarefas (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    evento_id BIGINT NOT NULL,
    titulo TEXT NOT NULL CHECK (char_length(titulo) BETWEEN 3 AND 100),
    descricao TEXT NOT NULL DEFAULT '' CHECK (char_length(descricao) <= 2000),
    status TEXT NOT NULL CHECK (status IN ('pendente', 'concluida')),
    prioridade TEXT NOT NULL CHECK (prioridade IN ('baixa', 'normal', 'alta')),
    fiscal_id BIGINT NOT NULL CHECK (fiscal_id IN (1, 2)),
    criado_em TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_guia_tarefas_evento
    ON guia_programacao.tarefas(evento_id);

"""Exemplo PostgreSQL: usa a mesma conexão SQLAlchemy do AppGrandesEventos.
As tabelas didáticas ficam no schema guia_programacao.
"""
from pathlib import Path
from sqlalchemy import text
from app.services.db import get_engine

BASE = Path(__file__).resolve().parent
FISCAIS = {1: "Ana — Fiscal", 2: "Bruno — Fiscal"}


def preparar():
    # Executado somente ao iniciar o laboratório, nunca ao importar o módulo.
    # Configure DATABASE_URL para um banco PostgreSQL de desenvolvimento.
    with get_engine().begin() as conn:
        sql = (BASE / "schema.sql").read_text(encoding="utf-8")
        for comando in sql.split(";"):
            if comando.strip():
                conn.execute(text(comando))


def validar(form):
    titulo = str(form.get("titulo", "")).strip()
    descricao = str(form.get("descricao", "")).strip()
    status = str(form.get("status", ""))
    prioridade = str(form.get("prioridade", ""))
    try:
        fiscal_id = int(form.get("fiscal_id", ""))
    except (TypeError, ValueError):
        raise ValueError("Selecione um fiscal válido.") from None
    if not 3 <= len(titulo) <= 100:
        raise ValueError("O título deve ter entre 3 e 100 caracteres.")
    if len(descricao) > 2000:
        raise ValueError("A descrição deve ter até 2000 caracteres.")
    if status not in {"pendente", "concluida"}:
        raise ValueError("Status inválido.")
    if prioridade not in {"baixa", "normal", "alta"}:
        raise ValueError("Prioridade inválida.")
    if fiscal_id not in FISCAIS:
        raise ValueError("Fiscal não encontrado.")
    return dict(titulo=titulo, descricao=descricao, status=status,
                prioridade=prioridade, fiscal_id=fiscal_id)


def listar(evento_id):
    with get_engine().connect() as conn:
        resultado = conn.execute(text("""
            SELECT * FROM guia_programacao.tarefas
            WHERE evento_id = :evento_id ORDER BY id DESC
        """), {"evento_id": int(evento_id)})
        return [dict(row) for row in resultado.mappings().all()]


def criar(evento_id, valores):
    with get_engine().begin() as conn:
        return conn.execute(text("""
            INSERT INTO guia_programacao.tarefas
                (evento_id, titulo, descricao, status, prioridade, fiscal_id)
            VALUES (:evento_id, :titulo, :descricao, :status, :prioridade, :fiscal_id)
            RETURNING id
        """), {**valores, "evento_id": int(evento_id)}).scalar_one()


def editar(evento_id, tarefa_id, valores, fiscal_id, coordenador):
    with get_engine().begin() as conn:
        parametros = {"evento_id": int(evento_id), "tarefa_id": int(tarefa_id)}
        atual = conn.execute(text("""
            SELECT * FROM guia_programacao.tarefas
            WHERE evento_id = :evento_id AND id = :tarefa_id
            FOR UPDATE
        """), parametros).mappings().first()
        if atual is None:
            raise ValueError("Tarefa não encontrada neste evento.")
        if not coordenador and (atual["fiscal_id"] != fiscal_id or valores["fiscal_id"] != fiscal_id):
            raise PermissionError("Você pode editar apenas suas tarefas e não pode reatribuí-las.")
        conn.execute(text("""
            UPDATE guia_programacao.tarefas
            SET titulo = :titulo, descricao = :descricao, status = :status,
                prioridade = :prioridade, fiscal_id = :fiscal_id
            WHERE evento_id = :evento_id AND id = :tarefa_id
        """), {**valores, **parametros})


def excluir(evento_id, tarefa_id):
    with get_engine().begin() as conn:
        resultado = conn.execute(text("""
            DELETE FROM guia_programacao.tarefas
            WHERE evento_id = :evento_id AND id = :tarefa_id
        """), {"evento_id": int(evento_id), "tarefa_id": int(tarefa_id)})
        return resultado.rowcount == 1

laboratorio:app --app-dir "guia de programação/exemplo_completo" --reload --port 8502
"""
import os
from contextlib import asynccontextmanager
import secrets
from pathlib import Path

from fastapi import FastAPI, Request
from fastapi.responses import RedirectResponse
from fastapi.staticfiles import StaticFiles
from fastapi.templating import Jinja2Templates
from starlette.middleware.sessions import SessionMiddleware

import dados_exemplo as dados

BASE = Path(__file__).resolve().parent
@asynccontextmanager
async def lifespan(app):
    dados.preparar()
    yield


app = FastAPI(title="Exemplo PostgreSQL — AppGrandesEventos", lifespan=lifespan)
app.add_middleware(SessionMiddleware, secret_key=os.environ.get("DEMO_SESSION_SECRET") or secrets.token_hex(32))
app.mount("/static", StaticFiles(directory=BASE / "static"), name="static")
templates = Jinja2Templates(directory=BASE / "templates")


def contexto(request):
    # Sessão simulada para estudar permissões, com IDs fictícios apenas no schema didático.
    request.session.setdefault("spreadsheet_id", 1)
    request.session.setdefault("fiscal_id", 1)
    request.session.setdefault("papel", "fiscal")
    return request.session


def pode_editar(session, tarefa):
    return session["papel"] == "coordenacao" or tarefa["fiscal_id"] == session["fiscal_id"]


def voltar(request, mensagem, erro=False):
    request.session["mensagem"] = {"texto": mensagem, "erro": erro}
    return RedirectResponse("/", status_code=303)


@app.get("/")
async def listar(request: Request):
    session = contexto(request)
    tarefas = dados.listar(session["spreadsheet_id"])
    for tarefa in tarefas:
        tarefa["pode_editar"] = pode_editar(session, tarefa)
    return templates.TemplateResponse(request, "tarefas.html", {
        "request": request, "tarefas": tarefas,
        "fiscais": dados.FISCAIS, "session": session,
        "mensagem": request.session.pop("mensagem", None),
        "total": len(tarefas),
        "pendentes": sum(t["status"] == "pendente" for t in tarefas),
    })


@app.post("/perfil")
async def perfil(request: Request):
    session = contexto(request)
    form = await request.form()
    perfil = str(form.get("perfil", ""))
    # Troca livre apenas nesta demonstração; não é autenticação.
    if perfil not in {"fiscal_1", "fiscal_2", "coordenacao"}:
        return voltar(request, "Perfil inválido.", True)
    session["papel"] = "coordenacao" if perfil == "coordenacao" else "fiscal"
    session["fiscal_id"] = 2 if perfil == "fiscal_2" else 1
    return voltar(request, "Perfil de demonstração alterado.")


@app.post("/tarefas")
async def criar(request: Request):
    session = contexto(request)
    form = await request.form()
    try:
        valores = dados.validar(form)
        if session["papel"] != "coordenacao" and valores["fiscal_id"] != session["fiscal_id"]:
            raise ValueError("O fiscal pode criar tarefas apenas para si.")
        dados.criar(session["spreadsheet_id"], valores)
    except ValueError as exc:
        return voltar(request, str(exc), True)
    return voltar(request, "Tarefa cadastrada.")


@app.post("/tarefas/{tarefa_id}/editar")
async def editar(request: Request, tarefa_id: int):
    session = contexto(request)
    form = await request.form()
    try:
        valores = dados.validar(form)
        # O serviço verifica também o registro atual dentro da transação.
        dados.editar(session["spreadsheet_id"], tarefa_id, valores,
                     session["fiscal_id"], session["papel"] == "coordenacao")
    except (ValueError, PermissionError) as exc:
        return voltar(request, str(exc), True)
    return voltar(request, "Alterações salvas.")


@app.post("/tarefas/{tarefa_id}/excluir")
async def excluir(request: Request, tarefa_id: int):
    session = contexto(request)
    if session["papel"] != "coordenacao":
        return voltar(request, "Somente a coordenação pode excluir tarefas.", True)
    if not dados.excluir(session["spreadsheet_id"], tarefa_id):
        return voltar(request, "Tarefa não encontrada neste evento.", True)
    return voltar(request, "Tarefa excluída.")

15 · Exercícios e verificação

1. Troque um rótulo

Altere “Nova tarefa” no botão e no popup. Procure no template e no JavaScript: o script redefine o título ao abrir. Confirme cadastro e edição.

2. Acrescente um campo Local

Defina a coluna no schema; adicione o input com name="local"; leia e valide no serviço; inclua no INSERT, UPDATE, listagem e preenchimento do popup. CREATE TABLE IF NOT EXISTS não altera tabelas existentes: prepare ALTER TABLE para o banco existente ou recrie apenas a base descartável do laboratório após guardar o que quiser manter.

3. Exija descrição ao concluir

Implemente a regra em validar(), compartilhada por cadastro e edição. Teste pendente sem descrição, concluída sem descrição e concluída com descrição.

4. Confira autorização

Crie uma tarefa como Ana. Troque para Bruno: a edição deve desaparecer. Um POST manual de edição como Bruno também deve ser recusado. Coordenação deve poder reatribuir; Ana não pode atribuir sua tarefa a Bruno.

Observe em Network

Estrutura de uma tela real: Coordenação

  1. main.py registra coordenacao.router e prepara sessão/contexto.
  2. get_coordenacao() em app/routers/coordenacao.py consulta os dados do evento e entrega o contexto ao template.
  3. coordenacao.html renderiza tabelas, formulário e popup.
  4. post_ticket_evento() lê o formulário e verifica o papel do usuário.
  5. salvar_ticket_evento() em postgres.py abre uma transação e verifica os registros com FOR UPDATE.
  6. O serviço grava nas tabelas tickets, ticket_ocorrencias, ticket_incidentes e ticket_fiscais conforme as regras.
  7. A rota registra auditoria e redireciona para recarregar a tela.

Estrutura de uma tela real: edição de emissão

get_consultar() carrega os registros visíveis no evento. consultar.js chama /api/pendencias, seleciona o ID e preenche o formulário. post_consultar_salvar() valida a permissão e os campos, e chama atualizar_campos_na_aba_mae(). Apesar do nome legado “aba”, a implementação grava no PostgreSQL. Na edição em popup, emissao_id identifica a emissão e ticket_id participa da autorização.

O que alterar para acrescentar um dado real

Se o novo dado pertence a uma emissão, siga a tabela ocorrencias em db/schema.sql, prepare uma migração e encontre as funções que fazem INSERT, UPDATE e SELECT dessa entidade. Depois siga o router, o name do input, o preenchimento em consultar.js, a resposta JSON da API, a auditoria e a sincronização offline. Acrescentar apenas o campo no HTML não cria persistência.

"""
Conexão com o banco PostgreSQL via SQLAlchemy.

A string de conexão é lida de:
  1. Variável de ambiente DATABASE_URL (prioritário), ou
  2. Arquivo .streamlit/secrets.toml, seção [database], chave url

Uso:
    from app.services.db import get_engine, SessionLocal
    with SessionLocal() as session:
        ...
"""

import os
import tomllib
from pathlib import Path

from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker


def _get_database_url() -> str:
    # 1. Tentar variável de ambiente
    url = os.environ.get("DATABASE_URL")
    if url:
        return url
    # 2. Tentar secrets.toml (padrão legado do Streamlit)
    secrets_path = Path(".streamlit/secrets.toml")
    if secrets_path.exists():
        with open(secrets_path, "rb") as f:
            secrets = tomllib.load(f)
        url = secrets.get("database", {}).get("url")
        if url:
            return url
    # 3. Fallback para desenvolvimento local
    return "postgresql+psycopg://appeventos:appeventos@127.0.0.1:5432/appeventos"


_engine = create_engine(
    _get_database_url(),
    pool_pre_ping=True,  # verifica conexão antes de usar
    pool_size=5,
    max_overflow=10,
    connect_args={"connect_timeout": 5},
    future=True,
)

SessionLocal = sessionmaker(bind=_engine, autoflush=False, future=True)


def get_engine():
    return _engine

def salvar_ticket_evento(
    evento_id: int,
    ocorrencia_ids: list[int],
    incidente_ids: list[int] | None = None,
    prioridade: str = "normal",
    observacoes: str | None = None,
    fiscal_ids: list[int] | None = None,
    usuario_fiscal: str = USR_FISCAL_ANATEL,
) -> int:
    """Cria um ticket para emissões e/ou incidentes selecionados."""
    with get_engine().begin() as conn:
        ids = list(dict.fromkeys(int(item) for item in ocorrencia_ids))
        incidentes = list(dict.fromkeys(int(item) for item in (incidente_ids or [])))
        if not ids and not incidentes:
            raise ValueError(
                "Selecione ao menos uma emissão ou incidente para abrir o ticket."
            )

        emissoes = (
            conn.execute(
                text("""
                    SELECT id, situacao, concluida_por, submetida_coordenador_em
                    FROM ocorrencias
                    WHERE evento_id = :evento_id
                      AND id = ANY(CAST(:ocorrencia_ids AS BIGINT[]))
                    FOR UPDATE
                """),
                {"evento_id": int(evento_id), "ocorrencia_ids": ids},
            )
            .mappings()
            .all()
        )
        emissoes_validas = [
            emissao
            for emissao in emissoes
            if (
                str(emissao["situacao"] or "").strip().casefold()
                == SITUACAO_PENDENTE.casefold()
                or (
                    emissao["submetida_coordenador_em"] is not None
                    and (
                        str(emissao["situacao"] or "").strip().casefold()
                        in {
                            "concluído",
                            "concluido",
                            SITUACAO_CONCLUIDA_FISCAL.casefold(),
                        }
                        and (emissao["concluida_por"] or "Fiscal") == "Fiscal"
                    )
                )
            )
        ]
        if len(emissoes_validas) != len(ids):
            raise ValueError(
                "Somente emissões pendentes ou emissões submetidas e concluídas pelo fiscal podem receber tickets."
            )

        emissao_ja_vinculada = conn.execute(
            text("""
                SELECT count(*)
                FROM ocorrencias o
                WHERE o.evento_id = :evento_id
                  AND o.id = ANY(CAST(:ocorrencia_ids AS BIGINT[]))
                  AND EXISTS (
                      SELECT 1
                      FROM ticket_ocorrencias toco
                      JOIN tickets t ON t.id = toco.ticket_id
                      WHERE toco.ocorrencia_id = o.id
                        AND t.evento_id = :evento_id
                  )
            """),
            {"evento_id": int(evento_id), "ocorrencia_ids": ids},
        ).scalar_one()
        if int(emissao_ja_vinculada) > 0:
            raise ValueError(
                "Uma ou mais emissões selecionadas já estão vinculadas a ticket."
            )

        if incidentes:
            incidentes_validos = (
                conn.execute(
                    text("""
                    SELECT id
                    FROM bsr_erb
                    WHERE evento_id = :evento_id
                      AND id = ANY(CAST(:incidente_ids AS BIGINT[]))
                      AND excluido_em IS NULL
                      AND submetido_coordenador_em IS NOT NULL
                """),
                    {"evento_id": int(evento_id), "incidente_ids": incidentes},
                )
                .scalars()
                .all()
            )
            if set(incidentes_validos) != set(incidentes):
                raise ValueError(
                    "Um ou mais incidentes não pertencem ao evento ou ainda não foram submetidos ao coordenador."
                )
            incidente_ja_vinculado = conn.execute(
                text("""
                    SELECT COUNT(*)
                    FROM ticket_incidentes vinculacao
                    JOIN tickets t ON t.id = vinculacao.ticket_id
                    WHERE vinculacao.incidente_id = ANY(CAST(:incidente_ids AS BIGINT[]))
                      AND t.evento_id = :evento_id
                """),
                {"evento_id": int(evento_id), "incidente_ids": incidentes},
            ).scalar_one()
            if int(incidente_ja_vinculado) > 0:
                raise ValueError(
                    "Um ou mais incidentes selecionados já estão vinculados a ticket."
                )

        ticket_id = conn.execute(
            text("""
                INSERT INTO tickets (evento_id, prioridade, observacoes)
                VALUES (:evento_id, :prioridade, :observacoes)
                RETURNING id
            """),
            {
                "evento_id": int(evento_id),
                "prioridade": prioridade,
                "observacoes": observacoes,
            },
        ).scalar_one()

        conn.execute(
            text("""
                INSERT INTO ticket_ocorrencias (ticket_id, ocorrencia_id)
                SELECT :ticket_id, unnest(CAST(:ocorrencia_ids AS BIGINT[]))
            """),
            {"ticket_id": int(ticket_id), "ocorrencia_ids": ids},
        )

        # Marca as emissões como submetidas ao coordenador
        conn.execute(
            text("""
                UPDATE ocorrencias
                SET submetida_coordenador_em = COALESCE(submetida_coordenador_em, now())
                WHERE id = ANY(CAST(:ocorrencia_ids AS BIGINT[]))
                  AND evento_id = :evento_id
            """),
            {"ocorrencia_ids": ids, "evento_id": int(evento_id)},
        )

        (
            conn.execute(
                text("""
                INSERT INTO ticket_incidentes (ticket_id, incidente_id)
                SELECT :ticket_id, unnest(CAST(:incidente_ids AS BIGINT[]))
            """),
                {"ticket_id": int(ticket_id), "incidente_ids": incidentes},
            )
            if incidentes
            else None
        )

        if incidentes:
            conn.execute(
                text("""
                    UPDATE bsr_erb
                    SET situacao = 'Pendente', concluida_por = NULL
                    WHERE evento_id = :evento_id
                      AND id = ANY(CAST(:incidente_ids AS BIGINT[]))
                """),
                {"evento_id": int(evento_id), "incidente_ids": incidentes},
            )

        for emissao in emissoes_validas:
            situacao_anterior = emissao["situacao"]
            conclusao_anterior = emissao["concluida_por"]
            conn.execute(
                text("""
                    INSERT INTO auditoria_ocorrencias (
                        ocorrencia_id, evento_id, usuario_fiscal, campo,
                        valor_anterior, valor_novo
                    ) VALUES (
                        :ocorrencia_id, :evento_id, :usuario_fiscal,
                        'Ticket vinculado', NULL, :valor_novo
                    )
                """),
                {
                    "ocorrencia_id": int(emissao["id"]),
                    "evento_id": int(evento_id),
                    "usuario_fiscal": usuario_fiscal,
                    "valor_novo": f"Ticket #{ticket_id}",
                },
            )
            if situacao_anterior == "Pendente" and conclusao_anterior is None:
                continue
            conn.execute(
                text("""
                    UPDATE ocorrencias
                    SET situacao = 'Pendente',
                        concluida_por = NULL,
                        atualizado_em = now()
                    WHERE evento_id = :evento_id AND id = :ocorrencia_id
                """),
                {
                    "evento_id": int(evento_id),
                    "ocorrencia_id": int(emissao["id"]),
                },
            )
            if situacao_anterior != "Pendente":
                conn.execute(
                    text("""
                        INSERT INTO auditoria_ocorrencias (
                            ocorrencia_id, evento_id, usuario_fiscal, campo,
                            valor_anterior, valor_novo
                        ) VALUES (
                            :ocorrencia_id, :evento_id, :usuario_fiscal,
                            'Situação', :valor_anterior, 'Pendente'
                        )
                    """),
                    {
                        "ocorrencia_id": int(emissao["id"]),
                        "evento_id": int(evento_id),
                        "usuario_fiscal": usuario_fiscal,
                        "valor_anterior": situacao_anterior,
                    },
                )
            if conclusao_anterior is not None:
                conn.execute(
                    text("""
                        INSERT INTO auditoria_ocorrencias (
                            ocorrencia_id, evento_id, usuario_fiscal, campo,
                            valor_anterior, valor_novo
                        ) VALUES (
                            :ocorrencia_id, :evento_id, :usuario_fiscal,
                            'Concluída por', :valor_anterior, NULL
                        )
                    """),
                    {
                        "ocorrencia_id": int(emissao["id"]),
                        "evento_id": int(evento_id),
                        "usuario_fiscal": usuario_fiscal,
                        "valor_anterior": conclusao_anterior,
                    },
                )

        conn.execute(
            text("DELETE FROM ticket_fiscais WHERE ticket_id = :ticket_id"),
            {"ticket_id": int(ticket_id)},
        )
        for fiscal_id in list(dict.fromkeys(int(item) for item in (fiscal_ids or []))):
            conn.execute(
                text("""
                    INSERT INTO ticket_fiscais (ticket_id, fiscal_id)
                    VALUES (:ticket_id, :fiscal_id)
                    ON CONFLICT DO NOTHING
                """),
                {"ticket_id": int(ticket_id), "fiscal_id": int(fiscal_id)},
            )
        return int(ticket_id)
