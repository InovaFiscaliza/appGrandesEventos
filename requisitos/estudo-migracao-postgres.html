Estudo de Migração

Eliminar dependência do Google Sheets e passar a usar exclusivamente o PostgreSQL

📄 AppGrandesEventos • 14/07/2026
Objetivo: tornar o AppGrandesEventos independente do Google Sheets, utilizando exclusivamente o banco PostgreSQL (já migrado e operacional) como única fonte de dados. Abaixo, o mapeamento completo de todos os arquivos que precisam ser alterados, com o passo a passo de cada modificação.

1. Visão geral da arquitetura atual

Hoje o fluxo de dados é:

  Navegador (HTML/JS)
       ↓ HTTP (POST/GET)
  Router FastAPI (app/routers/*.py)
       ↓ chama
  app/services/google_sheets.py  ← ÚNICA fonte de dados
       ↓
  Google Sheets (via gspread + API Google)

O que se deseja:

  Navegador (HTML/JS)
       ↓ HTTP (POST/GET)
  Router FastAPI (app/routers/*.py)
       ↓ chama
  app/services/postgres.py  ← ÚNICA fonte de dados
       ↓
  PostgreSQL (local, via SQLAlchemy)
Status: o arquivo app/services/postgres.py já existe e contém TODAS as funções necessárias com as mesmas assinaturas de google_sheets.py. Basta trocar os imports nos routers.

3. Routers FastAPI — 7 arquivos para modificar

Cada router importa funções de google_sheets e chama obter_cliente_gspread(). A mudança é sempre a mesma:

  1. Trocar o import de google_sheets para postgres
  2. Remover a chamada a obter_cliente_gspread()
  3. Passar spreadsheet_id diretamente como primeiro argumento

3.1. app/routers/selecao.py

O que mudar:

Atual (google_sheets)Novo (postgres)
from app.services.google_sheets import buscar_planilhas, obter_cliente_gspread from app.services.postgres import buscar_planilhas
client = obter_cliente_gspread()
eventos = buscar_planilhas(client) if client else {}		 eventos = buscar_planilhas()

Arquivo: app/routers/selecao.py — linhas 5 e 18

3.2. app/routers/menu.py

O que mudar: import e remoção do cliente.

AtualNovo
from app.services.google_sheets import (carregar_pendencias_painel_mapeadas, carregar_pendencias_abordagem_pendentes, carregar_pendencias_todas_estacoes, get_city_map_url, obter_cliente_gspread) from app.services.postgres import (carregar_pendencias_painel_mapeadas, carregar_pendencias_abordagem_pendentes, carregar_pendencias_todas_estacoes, get_city_map_url)
client = obter_cliente_gspread()

3.3. app/routers/inserir.py

O que mudar:

  • Trocar import de google_sheets para postgres
  • Remover client = obter_cliente_gspread() (linha 45)
  • Remover chamada a tentar_conexao_ou_offline(obter_cliente_gspread) (linha 97) — PostgreSQL é local
  • Todas as funções são chamadas sem client

Impacto no modo offline: A detecção de falha de conexão com Google Sheets deixa de fazer sentido. O formulário sempre consegue gravar no PostgreSQL local.

3.4. app/routers/consultar.py

O que mudar:

  • Trocar import de google_sheets para postgres (linhas 10-16)

8. Ordem de implementação recomendada

  1. Routers — alterar os 7 routers, um por vez, testando cada funcionalidade:
    1. selecao.py (escolha do evento)
    2. menu.py (tela principal)
    3. inserir.py (inserir emissão)
    4. consultar.py (editar pendência)
    5. bsr_erb.py (BSR/Jammer)
    6. busca.py (busca textual)
    7. tabela_ute.py (consulta UTE)
  2. Utilitários — revisar app/utils/offline.py:
    • Remover tentar_conexao_ou_offline() (Google Sheets offline não se aplica mais)
    • MANTER as demais funções (preparar_offline_ctx, extrair_dados_inserir, extrair_dados_edicao) para modo offline WhatsApp
  3. Frontend — manter todos os arquivos JS existentes (essenciais para o modo offline WhatsApp): app.js, sync.js, db.js, inserir.js, bsr_erb.js, consultar.js, connectivity.js
  4. Templates — manter blocos offline e scripts legados (necessários para o modo offline WhatsApp)
  5. Dependências — remover gspread e google-auth do pyproject.toml
  6. Limpeza — remover credenciais do Google (.streamlit/secrets.toml seção [gcp_service_account])
Resumo: 7 routers para modificar, postgres.py já está pronto. Todo o ecossistema offline (Service Worker, IndexedDB, filas de sincronização) DEVE SER MANTIDO para suportar o modo offline WhatsApp em áreas remotas. A mudança é segura e incremental, podendo ser feita router por router.
