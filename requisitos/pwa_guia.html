💡 O que é uma PWA e como o WhatsApp usa isso

Uma PWA (Progressive Web App) é um site que se comporta como um app nativo. O WhatsApp Web usa exatamente essa técnica: ele registra um Service Worker no navegador, que funciona como um proxy entre o app e a internet.

Quando a conexão cai, o Service Worker intercepta as requisições e serve páginas que estão salvas em cache local — por isso o WhatsApp continua abrindo mesmo offline.

1Usuário acessa o app com internet
→
2Service Worker é instalado e faz cache das páginas
→
3Internet cai
→
4SW serve do cache — app continua funcionando

⚙️ Passo 2 – app/static/sw.js

O Service Worker é um script JavaScript que roda em segundo plano no navegador, interceptando todas as requisições de rede. Usa a estratégia Network First com fallback para cache — igual ao WhatsApp.

📁 app/static/sw.js
const CACHE = "appEventos-v1";
const SHELL = [
  "/static/style.css",
  "/static/offline.html",
];

// Instalação: pré-carrega os assets essenciais
self.addEventListener("install", e => {
  e.waitUntil(
    caches.open(CACHE).then(c => c.addAll(SHELL))
  );
  self.skipWaiting();
});

// Ativação: remove caches de versões antigas
self.addEventListener("activate", e => {
  e.waitUntil(
    caches.keys().then(keys =>
      Promise.all(keys.filter(k => k !== CACHE).map(k => caches.delete(k)))
    )
  );
  self.clients.claim();
});

// Fetch: tenta a rede primeiro, cai para cache se offline
self.addEventListener("fetch", e => {
  if (e.request.method !== "GET") return;

  e.respondWith(
    fetch(e.request)
      .then(res => {
        const clone = res.clone();
        caches.open(CACHE).then(c => c.put(e.request, clone));
        return res;
      })
      .catch(() =>
        caches.match(e.request).then(cached =>
          cached || caches.match("/static/offline.html")
        )
      )
  );
});

Estratégia Network First

1Tenta buscar da rede (Google Sheets, etc.)
→
2Se ok: salva no cache e retorna
→
3Se falhou: busca do cache local
→
4Se não tem cache: mostra offline.html

🐍 Passo 5 – Rota /sw.js em main.py

O Service Worker deve ser servido da raiz (/sw.js), não de /static/sw.js. Adicione esta rota no main.py:

📁 main.py — adicionar após app.mount("/static", ...)
from fastapi.responses import FileResponse

@app.get("/sw.js", include_in_schema=False)
async def service_worker():
    return FileResponse("app/static/sw.js", media_type="application/javascript")
⚠️ Por que na raiz? O Service Worker só tem controle sobre URLs dentro do seu escopo. Um SW em /static/sw.js só controlaria páginas dentro de /static/. Na raiz (/sw.js), ele controla todo o app.

🗄️ Passo 6 – app/static/db.js (IndexedDB)

O IndexedDB é um banco de dados embutido no navegador. Ele salva os dados localmente, tornando-os disponíveis sem internet. Funciona como o armazenamento local do WhatsApp no celular.

Store: pendenciasPendências carregadas do Google Sheets para leitura offline
Store: fila_envioFormulários preenchidos offline aguardando envio
Store: frequenciasMapa de frequências para validação offline
📁 app/static/db.js
const DB_NAME = 'appEventos';
const DB_VER  = 1;
const STORES  = ['pendencias', 'fila_envio', 'frequencias'];

// Abre (ou cria) o banco de dados
function abrirDB() {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open(DB_NAME, DB_VER);
    req.onupgradeneeded = e => {
      const db = e.target.result;
      STORES.forEach(nome => {
        if (!db.objectStoreNames.contains(nome))
          db.createObjectStore(nome, { keyPath: 'id', autoIncrement: true });
      });
    };
    req.onsuccess = e => resolve(e.target.result);
    req.onerror   = e => reject(e.target.error);
  });
}

// Salva um array inteiro em uma store (substitui tudo)
async function salvarTodos(storeName, itens) {
  const db = await abrirDB();
  const tx = db.transaction(storeName, 'readwrite');
  tx.objectStore(storeName).clear();
  itens.forEach(item => tx.objectStore(storeName).add(item));
  return new Promise((res, rej) => {
    tx.oncomplete = () => res();
    tx.onerror    = e  => rej(e.target.error);
  });
}

// Lê todos os itens de uma store
async function lerTodos(storeName) {
  const db = await abrirDB();
  return new Promise((resolve, reject) => {
    const req = db.transaction(storeName, 'readonly')
                    .objectStore(storeName).getAll();
    req.onsuccess = e => resolve(e.target.result);
    req.onerror   = e => reject(e.target.error);
  });
}

// Adiciona um registro à fila de envio offline
async function enfileirar(payload) {
  const db = await abrirDB();
  return new Promise((resolve, reject) => {
    const req = db.transaction('fila_envio', 'readwrite')
                    .objectStore('fila_envio')
                    .add({ ...payload, timestamp: Date.now() });
    req.onsuccess = () => resolve();
    req.onerror   = e  => reject(e.target.error);
  });
}

// Remove da fila após envio bem-sucedido
async function removerDaFila(id) {
  const db = await abrirDB();
  db.transaction('fila_envio', 'readwrite')
    .objectStore('fila_envio').delete(id);
}

🔄 Passo 7 – app/static/sync.js (fila offline)

Detecta quando a internet volta e envia automaticamente os formulários preenchidos offline. Idêntico ao comportamento de mensagens pendentes do WhatsApp.

1Formulário enviado sem internet
→
2Salvo em fila_envio no IndexedDB
→
3Internet volta → evento online
→
4Fila enviada à API e removida do IndexedDB
📁 app/static/sync.js
// Requer db.js carregado antes deste script

async function sincronizarFila() {
  const fila = await lerTodos('fila_envio');
  if (fila.length === 0) return;

  console.log(`Sincronizando ${fila.length} item(ns) da fila...`);

  for (const item of fila) {
    try {
      const resp = await fetch(item.url, {
        method:  'POST',
        headers: { 'Content-Type': 'application/json' },
        body:    JSON.stringify(item.dados),
      });
      if (resp.ok) {
        await removerDaFila(item.id);
        console.log(`Item ${item.id} enviado e removido da fila.`);
      }
    } catch (e) {
      console.warn(`Falha ao enviar item ${item.id}:`, e);
    }
  }
}

// Executa ao recuperar conexão
window.addEventListener('online', sincronizarFila);
// Executa ao carregar a página (caso já esteja online)
if (navigator.onLine) sincronizarFila();

Interceptar submit do formulário (inserir.html)

📁 app/templates/inserir.html — adicionar no final do body
<script src="/static/db.js"></script>
<script src="/static/sync.js"></script>
<script>
  document.querySelector('form').addEventListener('submit', async e => {
    e.preventDefault();
    const dados = Object.fromEntries(new FormData(e.target));

    if (navigator.onLine) {
      // Online: envia direto para a API
      const resp = await fetch('/inserir', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(dados),
      });
      alert(resp.ok ? 'Enviado com sucesso!' : 'Erro ao enviar.');
    } else {
      // Offline: salva na fila do IndexedDB
      await enfileirar({ url: '/inserir', dados });
      alert('Sem internet. Salvo localmente — será enviado ao reconectar.');
    }
  });
</script>

Carregar dados do Google Sheets no IndexedDB (consultar.html)

📁 app/templates/consultar.html — carregar com fallback offline
<script src="/static/db.js"></script>
<script>
  async function carregarPendencias() {
    if (navigator.onLine) {
      // Online: busca da API FastAPI e salva no IndexedDB
      const resp  = await fetch('/api/pendencias');
      const dados = await resp.json();
      await salvarTodos('pendencias', dados);   // cacheia localmente
      return dados;
    } else {
      // Offline: usa o cache do IndexedDB
      console.warn('Offline — exibindo dados do cache local');
      return lerTodos('pendencias');
    }
  }

  carregarPendencias().then(dados => {
    // renderizar tabela com os dados recebidos...
    console.log('Pendências carregadas:', dados.length);
  });
</script>
