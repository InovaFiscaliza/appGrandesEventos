Guia de Migração — Google Sheets → PostgreSQL

Aplicação AppEventos (FastAPI + PWA offline)

📄 Documento de planejamento
Objetivo: substituir o backend de dados atual (Google Sheets via gspread) por um banco de dados relacional PostgreSQL, mantendo as funcionalidades existentes (inserção de emissões, consulta de pendências, busca, UTE, BSR/ERB e o modo offline com fila de sincronização).

1. Avaliação da situação atual

1.1. Como os dados funcionam hoje

Atualmente cada evento é uma planilha do Google (arquivo cujo nome contém "monitoracao"), e dentro dela cada aba (worksheet) guarda um tipo de dado:

Aba (worksheet)Papel atual
PAINELConsolidação de todas as ocorrências/pendências do evento
AbordagemEmissões verificadas em campo (colunas H–W) + BSR/ERB (colunas X–AC)
Tabela UTEUso Temporário de Espectro (País/Entidade, Local, Frequência, SEI)
LISTASListas de valores (dropdowns)
Abas de estaçãoUma aba por estação, com as ocorrências daquela estação

Constantes relevantes (ver app/config.py):

  • ABAS_SISTEMA = ["PAINEL", "Abordagem", "Tabela UTE", "Escala", "LISTAS"] → tudo que não está nessa lista é tratado como aba de estação.

O acesso é centralizado em app/services/google_sheets.py, que concentra ~todas as operações de leitura/escrita. Este é o único módulo que precisa ser reescrito para falar com o PostgreSQL.

1.2. Operações que o serviço expõe hoje (contrato a preservar)

Leitura

  • buscar_planilhas → lista de eventos disponíveis
  • listar_abas_estacoes → estações de um evento
  • get_city_map_url / obter_fuso_horario_evento → metadados do evento (lat/lon/fuso)
  • verificar_frequencia_existente / verificar_frequencia_global → checagem de duplicidade de frequência
  • carregar_dados_ute → Tabela UTE
  • carregar_pendencias_painel_mapeadas / carregar_pendencias_abordagem_pendentes / carregar_pendencias_todas_estacoes → pendências
  • carregar_todas_frequencias → mapa frequência → estação
  • carregar_opcoes_identificacao → opções do combobox

Escrita

  • inserir_emissao_I_W → nova emissão (Abordagem)
  • inserir_bsr_erb → registro de BSR/Jammer ou ERB
  • atualizar_campos_na_aba_mae / atualizar_campos_abordagem_por_id → edição de ocorrências
  • _buscar_por_texto_livre → busca textual
Regra de ouro da migração: manter as mesmas assinaturas de função (mesmos nomes e retornos: pd.DataFrame, str, bool, dict), trocando apenas a implementação interna. Assim os routers e views não precisam mudar.

2. Modelagem relacional proposta

O modelo "planilha por evento + aba por estação" vira um esquema normalizado:

2.1. DDL (script de criação)

Crie um arquivo db/schema.sql:

-- Extensão útil para busca textual sem acento
CREATE EXTENSION IF NOT EXISTS unaccent;
CREATE EXTENSION IF NOT EXISTS pg_trgm;

-- Um registro por evento (substitui "1 planilha = 1 evento")
CREATE TABLE eventos (
    id              BIGSERIAL PRIMARY KEY,
    nome            TEXT NOT NULL UNIQUE,
    legacy_sheet_id TEXT,                 -- id da planilha antiga (rastreio da migração)
    latitude        NUMERIC(9,6),
    longitude       NUMERIC(9,6),
    fuso_horario    TEXT DEFAULT 'America/Sao_Paulo',
    criado_em       TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Estações (substitui "abas de estação")
CREATE TABLE estacoes (
    id          BIGSERIAL PRIMARY KEY,
    evento_id   BIGINT NOT NULL REFERENCES eventos(id) ON DELETE CASCADE,
    nome        TEXT NOT NULL,
    latitude    NUMERIC(9,6),
    longitude   NUMERIC(9,6),
    UNIQUE (evento_id, nome)
);

-- Ocorrências/emissões (unifica PAINEL + Abordagem + abas de estação)
CREATE TABLE ocorrencias (
    id                BIGSERIAL PRIMARY KEY,
    evento_id         BIGINT NOT NULL REFERENCES eventos(id) ON DELETE CASCADE,
    estacao_id        BIGINT REFERENCES estacoes(id) ON DELETE SET NULL,
    local_regiao      TEXT,               -- "Local/Região" (inclui "Abordagem")
    fiscal            TEXT,
    data              DATE,
    hora              TIME,
    frequencia_mhz    NUMERIC(12,3),
    largura_khz       NUMERIC(12,3),
    faixa             TEXT,
    identificacao     TEXT,
    autorizado        TEXT,
    ute               BOOLEAN DEFAULT FALSE,
    processo_sei_ute  TEXT,
    observacoes       TEXT,
    alguem_ciente     TEXT,
    interferente      TEXT,
    situacao          TEXT NOT NULL DEFAULT 'Pendente',
    fonte             TEXT,               -- 'ABORDAGEM' | 'PAINEL' | 'ESTACAO' | 'BUSCA'
    criado_em         TIMESTAMPTZ NOT NULL DEFAULT now(),
    atualizado_em     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Índices para as consultas mais usadas
CREATE INDEX idx_ocorr_evento_situacao ON ocorrencias (evento_id, situacao);
CREATE INDEX idx_ocorr_frequencia      ON ocorrencias (evento_id, frequencia_mhz);
CREATE INDEX idx_ocorr_busca_trgm      ON ocorrencias USING gin (observacoes gin_trgm_ops);

-- Tabela UTE
CREATE TABLE tabela_ute (
    id              BIGSERIAL PRIMARY KEY,
    evento_id       BIGINT NOT NULL REFERENCES eventos(id) ON DELETE CASCADE,
    pais_entidade   TEXT,
    local           TEXT,
    frequencia_mhz  NUMERIC(12,3),
    processo_sei    TEXT
);
CREATE INDEX idx_ute_evento_freq ON tabela_ute (evento_id, frequencia_mhz);

-- BSR / Jammer / ERB (colunas X–AC da aba Abordagem)
CREATE TABLE bsr_erb (
    id          BIGSERIAL PRIMARY KEY,
    evento_id   BIGINT NOT NULL REFERENCES eventos(id) ON DELETE CASCADE,
    tipo        TEXT NOT NULL,           -- 'BSR/Jammer' | 'ERB'
    regiao      TEXT,
    latitude    NUMERIC(9,6),
    longitude   NUMERIC(9,6),
    criado_em   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Opções de identificação (substitui LISTAS / AC2:AC7)
CREATE TABLE opcoes_identificacao (
    id          BIGSERIAL PRIMARY KEY,
    evento_id   BIGINT REFERENCES eventos(id) ON DELETE CASCADE,  -- NULL = global
    valor       TEXT NOT NULL
);

-- Atualiza atualizado_em automaticamente
CREATE OR REPLACE FUNCTION set_atualizado_em() RETURNS trigger AS $$
BEGIN NEW.atualizado_em = now(); RETURN NEW; END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_ocorr_upd BEFORE UPDATE ON ocorrencias
FOR EACH ROW EXECUTE FUNCTION set_atualizado_em();
Observação: o "ID sequencial por aba" (coluna H da Abordagem) deixa de ser necessário — o BIGSERIAL do PostgreSQL passa a ser a chave primária. Se a aplicação exibe esse ID ao usuário, ele passa a ser o ocorrencias.id.

3.3. Camada de conexão (app/services/db.py)

import tomllib
from pathlib import Path
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

def _get_database_url() -> str:
    with open(Path(".streamlit/secrets.toml"), "rb") as f:
        return tomllib.load(f)["database"]["url"]

_engine = create_engine(_get_database_url(), pool_pre_ping=True, future=True)
SessionLocal = sessionmaker(bind=_engine, autoflush=False, future=True)

def get_engine():
    return _engine

4. Reescrita do serviço de dados

Crie app/services/postgres.py (ou substitua o conteúdo de google_sheets.py), mantendo os mesmos nomes de função. Exemplos de equivalência:

4.1. Listar eventos (era buscar_planilhas)

import pandas as pd
from sqlalchemy import text
from app.services.db import get_engine

def buscar_planilhas(_client=None) -> dict:
    with get_engine().connect() as conn:
        rows = conn.execute(text("SELECT nome, id FROM eventos ORDER BY nome")).all()
    return {nome: str(evento_id) for nome, evento_id in rows}

4.2. Pendências (era carregar_pendencias_*)

Toda a lógica de "achar a coluna certa por heurística" desaparece — no banco os campos têm nomes fixos:

def carregar_pendencias_todas_estacoes(_client, evento_id) -> pd.DataFrame:
    sql = text("""
        SELECT o.id AS "ID", COALESCE(e.nome, o.local_regiao) AS "Local",
               o.fiscal AS "Fiscal", o.data AS "Data", o.hora AS "HH:mm",
               o.frequencia_mhz AS "Frequência (MHz)", o.largura_khz AS "Largura (kHz)",
               o.faixa AS "Faixa de Frequência Envolvida", o.identificacao AS "Identificação",
               o.autorizado AS "Autorizado?", o.ute AS "UTE?",
               o.processo_sei_ute AS "Processo SEI UTE",
               o.observacoes AS "Ocorrência (observações)",
               o.alguem_ciente AS "Alguém mais ciente?", o.interferente AS "Interferente?",
               o.situacao AS "Situação", o.fonte AS "Fonte"
        FROM ocorrencias o
        LEFT JOIN estacoes e ON e.id = o.estacao_id
        WHERE o.evento_id = :ev AND lower(trim(o.situacao)) = 'pendente'
        ORDER BY "Local", "Data"
    """)
    return pd.read_sql(sql, get_engine(), params={"ev": evento_id})

4.3. Verificar frequência duplicada (era verificar_frequencia_*)

def verificar_frequencia_global(_client, evento_id, freq) -> str | None:
    if not freq or freq <= 0:
        return None
    with get_engine().connect() as conn:
        r = conn.execute(text("""
            SELECT COALESCE(e.nome, o.local_regiao)
            FROM ocorrencias o LEFT JOIN estacoes e ON e.id = o.estacao_id
            WHERE o.evento_id = :ev AND round(o.frequencia_mhz, 3) = round(:f, 3)
            LIMIT 1
        """), {"ev": evento_id, "f": float(freq)}).first()
    return r[0] if r else None

4.4. Inserir emissão (era inserir_emissao_I_W)

def inserir_emissao_I_W(_client, evento_id, dados: dict) -> bool:
    try:
        with get_engine().begin() as conn:   # begin() = transação automática
            conn.execute(text("""
                INSERT INTO ocorrencias
                  (evento_id, local_regiao, fiscal, data, hora, frequencia_mhz,
                   largura_khz, faixa, identificacao, autorizado, ute,
                   processo_sei_ute, observacoes, interferente, situacao, fonte)
                VALUES
                  (:ev, :local, :fiscal, :data, :hora, :freq, :bw, :faixa,
                   :ident, :autz, :ute, :proc, :obs, :inter, :situ, 'ABORDAGEM')
            """), {
                "ev": evento_id,
                "local": dados.get("Local/Região", "Abordagem"),
                "fiscal": dados.get("Fiscal", ""),
                "data": dados.get("Dia"), "hora": dados.get("Hora"),
                "freq": float(dados.get("Frequência em MHz", 0)),
                "bw": float(dados.get("Largura em kHz", 0)),
                "faixa": dados.get("Faixa de Frequência", ""),
                "ident": dados.get("Identificação", ""),
                "autz": dados.get("Autorizado? (Q)", ""),
                "ute": bool(dados.get("UTE?")),
                "proc": dados.get("Processo SEI ou Ato UTE", ""),
                "obs": f"{dados.get('Observações/Detalhes/Contatos','')} - {dados.get('Responsável pela emissão','')}",
                "inter": dados.get("Interferente?", ""),
                "situ": dados.get("Situação", "Pendente"),
            })
        return True
    except Exception:
        return False

4.5. Busca textual (era _buscar_por_texto_livre)

Use unaccent + ILIKE (ou pg_trgm) em vez de normalizar em Python:

def _buscar_por_texto_livre(_client, evento_id, termos, abas=None) -> pd.DataFrame:
    sql = text("""
        SELECT * FROM ocorrencias
        WHERE evento_id = :ev
          AND unaccent(lower(
                coalesce(local_regiao,'')||' '||coalesce(fiscal,'')||' '||
                coalesce(identificacao,'')||' '||coalesce(observacoes,'')
              )) LIKE unaccent(lower(:q))
    """)
    return pd.read_sql(sql, get_engine(),
                       params={"ev": evento_id, "q": f"%{termos}%"})
As demais funções (get_city_map_url, obter_fuso_horario_evento, carregar_dados_ute, inserir_bsr_erb, atualizar_campos_*, carregar_opcoes_identificacao) seguem o mesmo padrão: um SELECT/INSERT/UPDATE simples contra as tabelas do §2.

5. Script de migração dos dados existentes

Antes de desligar o Sheets, migre os dados uma única vez. Crie scripts/migrar_sheets_para_postgres.py:

"""Lê cada planilha do Google e grava no PostgreSQL. Rodar UMA vez."""
from app.services import google_sheets as gs      # serviço ANTIGO
from app.services.db import get_engine
from sqlalchemy import text

def migrar():
    client = gs.obter_cliente_gspread()
    planilhas = gs.buscar_planilhas(client)        # {nome: sheet_id}
    with get_engine().begin() as conn:
        for nome, sheet_id in planilhas.items():
            lat_lon = gs.get_city_map_url(client, sheet_id)  # extrair lat/lon
            fuso = gs.obter_fuso_horario_evento(client, sheet_id)
            evento_id = conn.execute(text("""
                INSERT INTO eventos (nome, legacy_sheet_id, fuso_horario)
                VALUES (:n, :sid, :fz)
                ON CONFLICT (nome) DO UPDATE SET legacy_sheet_id = EXCLUDED.legacy_sheet_id
                RETURNING id
            """), {"n": nome, "sid": sheet_id, "fz": fuso}).scalar()

            # Estações
            for est in gs.listar_abas_estacoes(client, sheet_id):
                conn.execute(text("""
                    INSERT INTO estacoes (evento_id, nome) VALUES (:ev, :n)
                    ON CONFLICT (evento_id, nome) DO NOTHING
                """), {"ev": evento_id, "n": est})

            # Ocorrências: use carregar_pendencias_* (ou get_all_values das abas)
            # e faça INSERT em ocorrencias mapeando cada coluna.
            # Tabela UTE: carregar_dados_ute -> INSERT em tabela_ute.
            print(f"Migrado: {nome} (evento_id={evento_id})")

if __name__ == "__main__":
    migrar()

Checklist da migração de dados:

  • Fazer backup (exportar as planilhas para XLSX/CSV) antes de começar.
  • Rodar o script em ambiente de teste primeiro.
  • Conferir contagem de linhas: SELECT count(*) FROM ocorrencias; vs. planilhas.
  • Validar frequências (tipos numéricos, vírgula → ponto).
  • Só então apontar a aplicação para o novo serviço.

6. Impacto no modo offline / PWA

O app tem uma camada offline (IndexedDB + fila de sincronização em app/static/db.js, sync.js, sw.js). Boa notícia: essa camada é independente do backend de dados — ela só precisa que o endpoint de escrita continue existindo.

O que muda:

  • O endpoint que hoje chama inserir_emissao_I_W passa a gravar no Postgres. A fila offline (enfileirar('fila_envio', dados)) e o replay ao reconectar continuam iguais.
  • Cuidado com IDs: como o ID agora é gerado pelo banco (BIGSERIAL), o cliente offline não deve inventar IDs. Envie os dados sem ID e deixe o INSERT retornar o id (RETURNING id).
  • Idempotência: para evitar duplicações quando a fila reenvia um item já gravado, gere um uuid no cliente e adicione uma coluna client_uuid TEXT UNIQUE em ocorrencias, usando INSERT ... ON CONFLICT (client_uuid) DO NOTHING.

7. Ordem de execução recomendada

  1. Provisionar o PostgreSQL (local via Docker ou serviço gerenciado).
  2. Rodar db/schema.sql (§2.1).
  3. Adicionar dependências e a seção [database] no secrets (§3).
  4. Criar app/services/db.py (§3.3).
  5. Implementar app/services/postgres.py mantendo o contrato (§4).
  6. Rodar o script de migração de dados em teste (§5).
  7. Trocar os imports nos routers/views (from app.services import google_sheets → postgres), ou renomear o novo arquivo para google_sheets.py.
  8. Testar: inserção, pendências, busca, UTE, BSR/ERB, e o fluxo offline.
  9. Remover gspread/google-auth do requirements.txt.

8. Riscos e pontos de atenção

  • Números com vírgula: o Sheets guarda 123,456; converter para . no script de migração (float(str(v).replace(",", "."))).
  • Datas/horas: padronizar formato ao migrar (DD/MM/YYYY → DATE).
  • Duplicidade de frequência: a checagem que hoje varre várias abas vira um único SELECT indexado (mais rápido e confiável).
  • Segredos: nunca commitar secrets.toml nem a DATABASE_URL.
  • Rollback: manter as planilhas antigas intactas até validar 100% do novo fluxo em produção.
